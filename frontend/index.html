Retrieval Algorithms

The core algorithms powering automatic query understanding and high-performance multilingual text retrieval.

KMP (Knuth-Morris-Pratt)

O(n + m)
What it does:

Finds an exact pattern inside text efficiently by precomputing a prefix table so matching never rewinds the text index.

Where it is used:

Exact document searching for single-keyword and phrase queries.

Time Complexity: O(n + m)

Rabin-Karp Rolling Hash

Avg O(n + m)
What it does:

Computes a sliding polynomial hash value for text windows, updating the hash in O(1) time as the window moves.

Where it is used:

Hash-based pattern matching and multi-string candidate verification.

Time Complexity: Average O(n + m), Worst O(n * m)

Trie (Prefix Tree)

O(m) Lookup
What it does:

Tree structure that stores words character-by-character along branches, allowing instant prefix navigation independent of total vocabulary size.

Where it is used:

Real-time prefix search and autocomplete suggestions.

Time Complexity: O(m) where m is keyword length

Aho-Corasick Automaton

O(n + z) Matching
What it does:

Builds a state machine with failure transitions across a Trie, locating multiple keywords simultaneously in a single linear pass.

Where it is used:

Multi-keyword queries searching several terms at once.

Time Complexity: O(n + z) where z is match count

Levenshtein Edit Distance

O(n * m) DP
What it does:

Calculates the minimum number of character insertions, deletions, and substitutions required to convert one word into another.

Where it is used:

Fuzzy search and automatic "Did you mean?" typo correction.

Time Complexity: O(n * m)

Suffix Array

O(n log² n)
What it does:

Stores sorted suffix starting positions for a text, enabling binary search lookups for arbitrary substrings.

Where it is used:

Advanced substring searching and full-text pattern indexing.

Time Complexity: O(n log² n) construction, O(m log n) lookup

Longest Common Prefix (LCP)

O(n) Kasai
What it does:

Measures the shared prefix lengths between consecutive suffixes in the Suffix Array using Kasai's linear algorithm.

Where it is used:

Discovering the longest repeated substrings and analyzing document content overlap.

Time Complexity: O(n)

About Multilingual Text Retrieval System

Multilingual Text Retrieval System is an intelligent, standalone search engine engineered for fast and accurate information discovery across multiple languages.

Automatic Query Routing

Users enter queries naturally without selecting algorithmic search modes. The system automatically analyzes token counts, prefix lengths, known vocabulary, and edit distance to deploy the optimal search algorithm dynamically.

Native Indic Script Support

Built-in UTF-8 Unicode processing natively handles English, Telugu, Hindi, and Tamil scripts without third-party converters, translation APIs, or external character transformations.

Pure Standalone Architecture

The system operates 100% offline with zero dependencies on external search engines, Elasticsearch, Lucene, or cloud AI services. All core algorithms are manually implemented.

Relevance Ranking

Discovered documents are scored on occurrence frequencies, title proximity, and pattern weights, ranked using a stable MergeSort algorithm to guarantee clean result presentation.
